# ROS 2 Launch Files

> **Topic:** Scale your ROS 2 application with Launch Files  
> **Focus:** XML Launch Files, Bringup Packages, Python Launch Files, Remappings, Parameters, and Namespaces

---

## 📌 Overview

As a ROS 2 application becomes larger, multiple nodes need to run together.

A real autonomous robot may contain:

- Camera node
- LiDAR node
- IMU node
- Motor controller node
- Localization node
- Mapping node
- Navigation node
- Perception node
- Controller node

Running every node manually in separate terminals quickly becomes difficult.

ROS 2 **Launch Files** solve this problem by allowing us to define how multiple nodes should be started and configured and then launch them together with a single command.

### Basic idea

```text
Multiple ROS 2 Nodes
        ↓
    Launch File
        ↓
 One Startup Command
        ↓
Organized Application
```

---

# 1. What is a ROS 2 Launch File?

A ROS 2 Launch File is a configuration file used to start and configure one or more ROS 2 nodes.

Without a launch file:

```bash
ros2 run my_py_pkg number_publisher
ros2 run my_py_pkg number_counter
```

With a launch file:

```bash
ros2 launch my_robot_bringup number_app.launch.xml
```

The launch file acts as the **startup configuration** for a ROS 2 application.

A launch file can be used to:

- Start multiple nodes
- Configure nodes
- Remap topics
- Load parameters
- Add namespaces
- Organize a complete robotic application

---

# 2. Why Use Launch Files?

Imagine a robot with 10–20 nodes.

Without launch files:

```text
Terminal 1 → Camera
Terminal 2 → LiDAR
Terminal 3 → IMU
Terminal 4 → SLAM
Terminal 5 → Nav2
Terminal 6 → Controller
...
```

With a launch file:

```text
                    Launch File
                        |
        ---------------------------------
        |       |       |       |       |
      Camera  LiDAR    IMU     SLAM    Nav2
       Node    Node    Node    Node    Node
```

## Main advantages

### 1. Start multiple nodes together

A single launch file can start several nodes.

### 2. Repeatable startup

The same application configuration can be launched repeatedly.

### 3. Centralized configuration

Parameters, remappings, namespaces, and node settings can be defined together.

### 4. Better organization

Launch configuration is separated from the implementation of individual nodes.

### 5. Useful for real robots

Large robotic systems usually require many components to work together.

# 7. Create the XML Launch File

Open:

```text
~/ros2_ws/src/my_robot_bringup/launch/number_app.launch.xml
```

Add:

```xml
<launch>

    <node pkg="my_py_pkg" exec="number_publisher"/>

    <node pkg="my_py_pkg" exec="number_counter"/>

</launch>
```

---

# 8. Understand the XML Launch File

## `<launch>`

```xml
<launch>
```

This is the root element of the launch file.

It tells ROS 2 that the file contains a launch description.

---

## `<node>`

Example:

```xml
<node pkg="my_py_pkg" exec="number_publisher"/>
```

The `<node>` element tells ROS 2 which executable should be started.

### `pkg`

```xml
pkg="my_py_pkg"
```

Specifies the ROS 2 package containing the executable.

### `exec`

```xml
exec="number_publisher"
```

Specifies the executable that should be started.

Therefore:

```xml
<node pkg="my_py_pkg" exec="number_publisher"/>
```

means:

> Start the `number_publisher` executable from the `my_py_pkg` package.

Similarly:

```xml
<node pkg="my_py_pkg" exec="number_counter"/>
```

starts the `number_counter` executable.

---

# 9. How the Launch System Works

The complete flow is:

```text
number_app.launch.xml
          |
          ↓
     ROS 2 Launch
          |
      -------------
      |           |
      ↓           ↓
number_       number_
publisher     counter
```

When the launch file is executed, ROS 2 reads the configuration and starts both executables.

# 10. Why Use a Separate Bringup Package?

The `my_robot_bringup` package separates:

```text
Node implementation
        from
Application startup/configuration
```

A bringup package can contain:

```text
robot_bringup/
├── launch/
├── config/
├── rviz/
└── package.xml
```

For larger robotic applications, this can contain:

- Launch files
- Parameters
- RViz configurations
- Robot startup configuration

This separation makes a workspace easier to understand and maintain.

# 11. Install the Launch File

Creating the launch file is not enough.

The launch file must be installed so ROS 2 can find it after the package is built.

Open:

```text
~/ros2_ws/src/my_robot_bringup/CMakeLists.txt
```

Add:

```cmake
install(DIRECTORY
    launch
    DESTINATION share/${PROJECT_NAME}/
)
```

## What this means

```cmake
install(DIRECTORY
```

We are installing a directory.

```cmake
launch
```

This is the directory that should be installed.

```cmake
DESTINATION
```

Specifies where it should be installed.

```cmake
share/${PROJECT_NAME}/
```

`${PROJECT_NAME}` refers to the package name.

For this project:

```text
my_robot_bringup
```

---

# 12. Add the Package Dependency

Open:

```text
~/ros2_ws/src/my_robot_bringup/package.xml
```

Add:

```xml
<exec_depend>my_py_pkg</exec_depend>
```

This declares that `my_robot_bringup` requires `my_py_pkg` at runtime.

For the CMake-based bringup package, make sure the package also declares the appropriate build type:

```xml
<export>
    <build_type>ament_cmake</build_type>
</export>
```

# 19. Python Launch Files

ROS 2 also supports Python launch files.

A simple Python launch file looks like:

```python
from launch import LaunchDescription
from launch_ros.actions import Node


def generate_launch_description():

    return LaunchDescription([

        Node(
            package='my_py_pkg',
            executable='number_publisher'
        ),

        Node(
            package='my_py_pkg',
            executable='number_counter'
        )

    ])
```

The Python approach is useful when launch behavior requires more programmatic logic or dynamic configuration.

---

# 20. XML vs Python Launch Files

| XML | Python |
|---|---|
| Simple | Programmable |
| Readable | Flexible |
| Declarative | Supports Python logic |
| Good for straightforward configurations | Useful for more complex launch configurations |

### XML example

```xml
<node pkg="my_py_pkg" exec="number_publisher"/>
```

### Python example

```python
Node(
    package='my_py_pkg',
    executable='number_publisher'
)
```

The important concept is:

> A launch file describes how a ROS 2 application should be started and configured.

# 21. Remappings in Launch Files

Launch files can also configure topic remappings.

Suppose a node normally publishes:

```text
/number
```

but we want it to publish:

```text
/my_number
```

The launch configuration can define the remapping.

Conceptually:

```text
Node
 |
 | /number
 ↓
Remapping
 |
 ↓
/my_number
```

Remapping allows communication names to be changed without modifying the node's source code.

---

# 22. Parameters in Launch Files

ROS 2 nodes can have parameters.

For example:

```text
number = 10
```

A launch file can provide parameter values when starting a node.

This allows the same node to run with different configurations without changing the node's source code.

Conceptually:

```text
Launch File
     |
     ↓
Node + Parameters
     |
     ↓
Configured Node
```

# 23. Namespaces in Launch Files

Namespaces help organize nodes and communication resources.

For example:

```text
/robot1/camera
/robot1/lidar

/robot2/camera
/robot2/lidar
```

Namespaces are especially useful for:

- Multi-robot systems
- Large robotic applications
- Simulation
- Reusable robot configurations

# 25. Common Mistakes

## Mistake 1 — Forgetting to build

After creating or modifying a launch file:

```bash
colcon build
```

may be required before running the updated installed launch file.

---

## Mistake 2 — Forgetting to source

After building:

```bash
source install/setup.bash
```

Otherwise ROS 2 may not find the newly built package.

---

## Mistake 3 — Incorrect package name

Make sure:

```xml
pkg="my_py_pkg"
```

matches the actual package name.

---

## Mistake 4 — Incorrect executable name

Make sure:

```xml
exec="number_publisher"
```

matches an executable registered by the package.

For a Python package, this normally corresponds to an entry in `setup.py`.

---

## Mistake 5 — Launch directory not installed

Make sure `CMakeLists.txt` contains:

```cmake
install(DIRECTORY
    launch
    DESTINATION share/${PROJECT_NAME}/
)
```

---

## Mistake 6 — Missing dependency

Make sure the launch package declares:

```xml
<exec_depend>my_py_pkg</exec_depend>
```
