ROS2 Learning Series — Day 7

Scale Your Application with ROS2 Launch Files

Overview

As a ROS2 application becomes larger, it may contain many nodes that need to run together.

For example, a real robot may have:

Camera node

LiDAR node

IMU node

Motor controller node

Localization node

Mapping node

Navigation node

Perception node

Controller node

Running every node manually in separate terminals becomes difficult to manage.

This is where ROS2 Launch Files are useful.

A Launch File allows us to define how multiple ROS2 nodes should be started and configured, and then launch them together using a single command.

1. What is a ROS2 Launch File?

A ROS2 Launch File is a configuration file used to start and configure one or more ROS2 nodes.

Instead of:

ros2 run my_py_pkg number_publisher
ros2 run my_py_pkg number_counter

we can define both nodes inside one launch file and start them together:

ros2 launch my_robot_bringup number_app.launch.xml

A launch file therefore acts as a startup configuration for a ROS2 application.

It can be used to:

Start multiple nodes

Configure nodes

Remap topics

Load parameters

Add namespaces

Organize a complete robotic application

2. Why Do We Use Launch Files?

Imagine a robot with 10 nodes.

Without a launch file, we may need many terminals and manual commands.

With a launch file:

                ROS2 Launch File
                       |
        --------------------------------
        |       |       |       |       |
      Camera  LiDAR    IMU   SLAM    Nav2
       Node    Node    Node   Node    Node

Main advantages

1. Start multiple nodes together

A single launch file can start several nodes.

2. Repeatable startup

The same application configuration can be launched repeatedly.

3. Easier configuration

Parameters, remappings and namespaces can be defined in one place.

4. Better organization

Launch files separate application startup/configuration from node implementation.

5. Useful for real robots

Large robotic systems commonly require multiple nodes to work together.

3. Launch File Types

ROS2 supports different launch-file formats.

Common formats include:

XML

Python

YAML is commonly used alongside launch systems for configuration and parameters.

In this Day 7 exercise, the focus is on XML Launch Files and an introduction to Python Launch Files.

4. XML Launch File

An XML launch file uses XML syntax.

Example:

<launch>
    <node pkg="my_py_pkg" exec="number_publisher"/>
    <node pkg="my_py_pkg" exec="number_counter"/>
</launch>

The <launch> element is the root element.

Inside it, we define the nodes that should be started.

5. Understanding the <node> Tag

Consider:

<node pkg="my_py_pkg" exec="number_publisher"/>

pkg

pkg="my_py_pkg"

Specifies the ROS2 package containing the executable.

exec

exec="number_publisher"

Specifies the executable that should be started.

Therefore:

<node pkg="my_py_pkg" exec="number_publisher"/>

means:

Start the number_publisher executable from the my_py_pkg package.

Similarly:

<node pkg="my_py_pkg" exec="number_counter"/>

starts the number_counter executable.

6. Day 7 Project

For this exercise, we create a separate package:

my_robot_bringup

my_py_pkg

7. Create the Launch Package

Go to the src directory:

cd ~/ros2_ws/src

Create the package:

ros2 pkg create my_robot_bringup

Enter the package:

cd my_robot_bringup

Remove the automatically created directories if they are not required:

rm -r include/ src/

Create the launch directory:

mkdir launch

Enter the launch directory:

cd launch

Create the XML launch file:

touch number_app.launch.xml

9. Create the XML Launch File

Open:

~/ros2_ws/src/my_robot_bringup/launch/number_app.launch.xml

Add:

<launch>

    <node pkg="my_py_pkg" exec="number_publisher"/>

    <node pkg="my_py_pkg" exec="number_counter"/>

</launch>

10. How the Launch File Works

When ROS2 reads:

<launch>

it knows this is a launch description.

Then:

<node pkg="my_py_pkg" exec="number_publisher"/>

starts the publisher node.

And:

<node pkg="my_py_pkg" exec="number_counter"/>

starts the counter node.

Conceptually:

number_app.launch.xml
          |
          ↓
     ROS2 Launch
          |
     -------------
     |           |
     ↓           ↓
number_       number_
publisher     counter

12. Install the Launch File

Creating a launch file is not enough.

The launch file must also be installed so ROS2 can find it after building the workspace.

Open:

my_robot_bringup/CMakeLists.txt

Add:

install(DIRECTORY
    launch
    DESTINATION share/${PROJECT_NAME}/
)

This tells the build system to install the launch directory into the package's share directory.

13. Understanding the CMake Installation

install(DIRECTORY
    launch
    DESTINATION share/${PROJECT_NAME}/
)

install(DIRECTORY

We are installing a directory.

launch

This is the directory we want to install.

DESTINATION

Specifies where it should be installed.

${PROJECT_NAME}

Refers to the package name.

For this package:

my_robot_bringup

14. Add Dependency in package.xml

Because the launch package starts executables from:

my_py_pkg

add this dependency in:

my_robot_bringup/package.xml

<exec_depend>my_py_pkg</exec_depend>

This tells ROS2 that my_robot_bringup requires my_py_pkg at runtime.

For the CMake-based bringup package, make sure the package also declares the appropriate build type:

<export>
    <build_type>ament_cmake</build_type>
</export>

21. Python Launch Files

ROS2 also supports Python launch files.

A simple Python launch file looks like:

from launch import LaunchDescription
from launch_ros.actions import Node


def generate_launch_description():

    return LaunchDescription([

        Node(
            package='my_py_pkg',
            executable='number_publisher'
        ),

        Node(
            package='my_py_pkg',
            executable='number_counter'
        )
    ])

The Python approach is useful when launch behavior requires more programmatic logic or dynamic configuration.

23. Remappings in Launch Files

Launch files can also configure topic remappings.

Suppose a node normally publishes:

/number

but we want it to publish:

/my_number

A launch configuration can define this remapping.

Conceptually:

Node
 |
 | /number
 ↓
Remapping
 |
 ↓
/my_number

Remapping allows communication names to be changed without modifying the node's source code.

24. Parameters in Launch Files

ROS2 nodes can have parameters.

For example:

number = 10

A launch file can provide parameter values when starting a node.

This allows the same node to run with different configurations without changing its source code.

Conceptually:

Launch File
     |
     ↓
Node + Parameters
     |
     ↓
Configured Node

27. Common Mistakes

Mistake 1 — Forgetting to build

After creating or modifying a launch file:

colcon build

may be required before running the updated installed launch file.

Mistake 2 — Forgetting to source

After building:

source install/setup.bash

Otherwise ROS2 may not find the newly built package.

Mistake 3 — Incorrect package name

Make sure:

pkg="my_py_pkg"

matches the actual package name.

Mistake 4 — Incorrect executable name

Make sure:

exec="number_publisher"

matches an executable registered by the package.

For a Python package, this normally corresponds to an entry in setup.py.

Mistake 5 — Launch directory not installed

Make sure CMakeLists.txt contains:

install(DIRECTORY
    launch
    DESTINATION share/${PROJECT_NAME}/
)

Mistake 6 — Missing dependency

Make sure the launch package declares:

<exec_depend>my_py_pkg</exec_depend>
