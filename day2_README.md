## 📖 What I Learned Today

### What is a Workspace?
A **workspace** (`ros2_ws`) is the project folder where all packages and nodes live.

```bash
mkdir ros2_ws
cd ros2_ws
mkdir src
colcon build
```

### What is a Package?
A **package** is a collection of related ROS2 code and files that work together to perform a specific function.

Examples:
- `motor_controller` → code to control the motor
- `camera_driver` → code related to the camera

Packages come in two types — Python and C++.

**Create a Python package:**
```bash
cd src
ros2 pkg create my_py_pkg --build-type ament_python --dependencies rclpy
```

**Create a C++ package:**
```bash
ros2 pkg create my_cpp_pkg --build-type ament_cmake --dependencies rclcpp
```

> ⚠️ Note: C++ packages depend on `rclcpp` (not `rclpy`, which is the Python client library).

### What is a Node?
A **node** is an individual program responsible for one specific function of the robot. Each node has a single, focused responsibility.

Examples: `camera_node`, `lidar_node`, `motor_node`, `navigation_node`

This is core to ROS2's design — instead of one large program, a robot's behavior is split into small, independent nodes that communicate with each other.

## 🗂️ Workspace Folder Architecture

```
ros2_ws/                               ← workspace root
├── build/                             ← generated by colcon build (ignored in git)
├── install/                           ← generated by colcon build (ignored in git)
├── log/                                ← build/run logs (ignored in git)
└── src/                                ← all source packages live here
    │
    ├── my_py_pkg/                      ← Python package
    │   ├── package.xml                 ← package metadata + dependencies
    │   ├── setup.py                    ← build config + entry points (executables)
    │   ├── setup.cfg
    │   ├── resource/
    │   │   └── my_py_pkg
    │   └── my_py_pkg/                  ← actual Python module folder
    │       ├── __init__.py
    │       └── my_first_node.py        ← node code
    │
    └── my_cpp_pkg/                     ← C++ package
        ├── package.xml                 ← package metadata + dependencies
        ├── CMakeLists.txt              ← build config + executables
        ├── include/
        │   └── my_cpp_pkg/
        └── src/
            └── my_first_node.cpp       ← node code
```

## 🐍 Writing a Python Node

```bash
cd ros2_ws/src/my_py_pkg/my_py_pkg
touch my_first_node.py
chmod +x my_first_node.py
```

```python
#!/usr/bin/env python3
import rclpy
from rclpy.node import Node

class MyNode(Node):

    def __init__(self):
        super().__init__("py_test")
        self.get_logger().info("Hello World")
        self.create_timer(1.0, self.time_callback)

    def time_callback(self):
        self.get_logger().info("Hello")

def main(args=None):
    rclpy.init(args=args)
    node = MyNode()
    rclpy.spin(node)
    rclpy.shutdown()

if __name__ == "__main__":
    main()
```

### `setup.py` — registering the node as a runnable executable
Add the node under `entry_points` so `ros2 run` can find it:
```python
entry_points={
    'console_scripts': [
        'py_node = my_py_pkg.my_first_node:main'
    ],
},
```

### `package.xml` — declares the package's dependencies
Ensures `rclpy` is listed as a dependency so colcon knows what to build against.

### Build & run
```bash
cd ros2_ws
colcon build
source install/setup.bash
ros2 run my_py_pkg py_node
```

## 🧩 Writing a C++ Node

```bash
cd ros2_ws/src/my_cpp_pkg/src
touch my_first_node.cpp
```

```cpp
#include "rclcpp/rclcpp.hpp"

class MyNode : public rclcpp::Node
{
  public:
    MyNode() : Node("cpp_test"), counter_(0)
    {
        RCLCPP_INFO(this->get_logger(), "Hello World");
        timer_ = this->create_wall_timer(
            std::chrono::seconds(1),
            std::bind(&MyNode::timerCallback, this));
    }

  private:
    void timerCallback()
    {
        RCLCPP_INFO(this->get_logger(), "Hello %d", counter_);
        counter_++;
    }
    rclcpp::TimerBase::SharedPtr timer_;
    int counter_;
};

int main(int argc, char **argv)
{
    rclcpp::init(argc, argv);
    auto node = std::make_shared<MyNode>();
    rclcpp::spin(node);
    rclcpp::shutdown();
    return 0;
}
```

### `CMakeLists.txt` — registering the executable
```cmake
add_executable(cpp_node src/my_first_node.cpp)
ament_target_dependencies(cpp_node rclcpp)
```

### `package.xml` — declares the package's dependencies
Ensures `rclcpp` is listed so colcon links against the correct client library.

### Build & run
```bash
cd ros2_ws
colcon build
ros2 run my_cpp_pkg my_first_node
```

## 🔑 Key Takeaway

**Packages** organize *what* code belongs together; **nodes** define *how* that code runs as independent, communicating units. `package.xml` tells the build system what a package depends on, while `setup.py` (Python) and `CMakeLists.txt` (C++) tell it what to actually build and how to expose it as a runnable node via `ros2 run`.
